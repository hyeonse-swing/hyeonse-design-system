# Review or document

For review, inspect the rendered screen and its actual interactions. Rank findings by impact on task completion, readability, access, and consistency. Give an element, trigger, observed effect, and actionable correction. Distinguish an observed defect from a code-only suspicion and do not invent browser proof.

For component documentation, read implementation and real call sites first. State purpose, when to use, public API, meaningful states, keyboard behavior, responsive behavior, and known limits. Include an example that compiles against the exported API. If the element is only showcase markup or a local app pattern, label it that way instead of documenting it as a package export.
