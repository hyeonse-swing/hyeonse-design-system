# Package integration

Use the **installed version** as the source for exact names, types, token values, and examples. Run `npm exec --no -- hds list`, `hds show <export-name>`, `hds tokens [name]`, or `hds example <id>` in a consumer project; inside this repository use `npm run hds -- ...`. Each command accepts `--json`. The public `./catalog.json` and `./catalog.schema.json` exports and package-root `llms.txt` / `llms-full.txt` offer file-based lookup. Check the public TypeScript declarations for the version you are using; this reference is not a complete API snapshot.

The runtime/style entrypoints are `./tokens.css`, `./components.css`, `./preferences`, and `./react`. Import both CSS files when using the current React preference controls. The `.hds-*` styles currently serve `ThemeToggle` and `PreferencesPanel`; showcase Button and Input markup does not mean the package exports those React components. Consumer-specific cards and other UI remain in the app.

`./preferences` exports `preferencesKey`, `defaultPreferences`, validation/parse/serialize helpers, `resolvedTheme`, `effectiveMotion`, `createPreferenceScript(storageKey?, defaults?)`, and `preferenceScript`. The default key is `hyeonse-site-preferences`. `Preferences` has `theme`, `accent`, `density`, `corners`, and `motion`; the default values are `system`, `cobalt`, `comfortable`, `crisp`, and `full`. Place the initial script in the document head before CSS paints. Valid saved choices take priority over site defaults.

`./react` exports `PreferencesProvider`, `usePreferences`, `ThemeToggle`, and `PreferencesPanel`. The Provider accepts `storageKey?`, `eventName?` (default `hyeonse:preferences`), and `defaults?: Partial<Preferences>`; the hook gives `preferences`, `setPreference`, and `resetPreferences`. The controls accept `locale='ko'|'en'`. Match a custom script storage key and defaults with the Provider. Inspect the target framework's document-head and client-component integration before applying the example.
