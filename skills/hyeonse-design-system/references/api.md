# Package integration

Use the **installed version** for exact exports, types, token values, and examples. Install the versioned v0.4.0 package archive with `npm install https://design-system.hyeonse.dev/releases/hyeonse-design-system-0.4.0.tgz`. Check the release `version`, `url`, `sha256`, and `integrity` in https://design-system.hyeonse.dev/releases/manifest.json. The older GitHub `v0.3.0` tag (`npm install github:hyeonse-swing/hyeonse-design-system#v0.3.0`) contains only the four primitive components and expanded tokens; `v0.2.0` does not include primitives. The v0.4.0 archive is a direct website package release, not an npm registry or GitHub v0.4.0 tag release.

Run `npm exec --no -- hds list`, `hds show <export-name>`, `hds tokens [name]`, `hds search <words>`, or `hds example <id>` in a consumer project; here use `npm run hds -- ...`. Search includes states, conditions, and token values. Each command accepts `--json`. The schema remains version 1. The public `./catalog.json` and `./catalog.schema.json` exports and package-root `llms.txt` / `llms-full.txt` offer file lookup. `entry.props` lists component-declared props only; `hds show` type context or the public `.d.ts` contains inherited native DOM attributes and refs.

Import `./tokens.css` and `./components.css` once, in that order. They provide semantic tokens and packaged control classes without a global reset. `./preferences` and `./react` retain the existing settings API. v0.3.0 adds `./primitives`: named `Button`, `TextField`, `Checkbox`, `Badge` functions and their Props types. Native attributes and React 19 refs pass through. The v0.4.0 archive also provides `./layout` (`SizeProvider`, `Container`, `Stack`, `Inline`, `Grid`), `./fields` (`Input`, `Select`, and other fields), `./overlays` (`Dialog`, menus, and notifications), and `./display` (`Card`, tabs, tables, and feedback). These subpaths require React and React DOM 19; fields, overlays, and display use the packaged Base UI runtime dependency. They are absent from the public v0.3.0 tag. See [component usage](../../../docs/components.md) for contracts, states, and accessibility.

v0.4.0 components and layouts accept `size?: 'xs' | 'sm' | 'md' | 'lg' | 'xl'`; `SizeProvider` requires `size`. Omitted sizes inherit from the nearest provider or layout and default to `md`; an explicit child size wins. Open portal content retains its resolved size. Native numeric input width is `inputSize?: number` on applicable input components, separate from visual `size`. Query the installed version before using these APIs.

`./preferences` exports `preferencesKey`, `defaultPreferences`, validation/parse/serialize helpers, `resolvedTheme`, `effectiveMotion`, `createPreferenceScript(storageKey?, defaults?)`, and `preferenceScript`. The default key is `hyeonse-site-preferences`. `Preferences` has `theme`, `accent`, `density`, `corners`, and `motion`; defaults are `system`, `cobalt`, `comfortable`, `crisp`, `full`. Put the initial script in the document head before CSS paints. Valid saved choices take priority over site defaults. System reduced motion takes priority over the saved motion preference.

`./react` exports `PreferencesProvider`, `usePreferences`, `ThemeToggle`, and `PreferencesPanel`. The Provider accepts `storageKey?`, `eventName?` (default `hyeonse:preferences`), and `defaults?: Partial<Preferences>`; the hook gives `preferences`, `setPreference`, and `resetPreferences`. The controls accept `locale='ko'|'en'`. Match a custom script storage key and defaults with the Provider. Inspect the target framework's document-head and client-component integration before applying the example.

Base UI 1.9.0 leaves a WebKit VoiceOver focus-guard accessible-name issue unresolved ([upstream #5237](https://github.com/mui/base-ui/issues/5237)). Browser automation and DOM focus checks do not establish the actual VoiceOver reading experience; see [browser verification limits](../../../docs/code-freeze.md#브라우저-검사-범위).
