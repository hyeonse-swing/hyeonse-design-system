# Package integration

Use the **target app's installed version** for exact exports, types, token values, and examples. For a new installation, read the current website release manifest at https://design-system.hyeonse.dev/releases/manifest.json and install its versioned archive URL; verify its `version`, `url`, `sha256`, and `integrity`. Do not assume the copied skill's version is current. The older GitHub `v0.3.0` tag (`npm install github:hyeonse-swing/hyeonse-design-system#v0.3.0`) contains only the four primitive components and expanded tokens; `v0.2.0` does not include primitives. The v0.4.x archives are direct website releases, not npm registry or GitHub v0.4.x tag releases.

Run `npm exec --no -- hds list`, `hds show <export-name>`, `hds tokens [name]`, `hds search <words>`, or `hds example <id>` in a consumer project; here use `npm run hds -- ...`. Search includes states, conditions, and token values. Each command accepts `--json`. The schema remains version 1. The public `./catalog.json` and `./catalog.schema.json` exports and package-root `llms.txt` / `llms-full.txt` offer file lookup. `entry.props` lists component-declared props only; `hds show` type context or the public `.d.ts` contains inherited native DOM attributes and refs.

Import `@hyeonse/design-system/tokens.css` and `@hyeonse/design-system/components.css` once, in that order, at the app's global CSS entry. They provide semantic tokens and packaged control classes without a global reset. Check existing global styles for conflicting tokens and resets. `./preferences` and `./react` retain the existing settings API. v0.3.0 adds `./primitives`: named `Button`, `TextField`, `Checkbox`, `Badge` functions and their Props types. Native attributes and React 19 refs pass through. The v0.4.0 archive also provides `./layout` (`SizeProvider`, `Container`, `Stack`, `Inline`, `Grid`), `./fields` (`Input`, `Select`, and other fields), `./overlays` (`Dialog`, menus, and notifications), and `./display` (`Card`, tabs, tables, and feedback). These subpaths require React and React DOM 19; fields, overlays, and display use the packaged Base UI runtime dependency. They are absent from the public v0.3.0 tag. For component details, read `docs/components.md` inside the installed package.

v0.4.0 components and layouts accept `size?: 'xs' | 'sm' | 'md' | 'lg' | 'xl'`; `SizeProvider` requires `size`. Omitted sizes inherit from the nearest provider or layout and default to `md`; an explicit child size wins. Open portal content retains its resolved size. Native numeric input width is `inputSize?: number` on applicable input components, separate from visual `size`. Query the installed version before using these APIs.

`./preferences` exports `preferencesKey`, `defaultPreferences`, validation/parse/serialize helpers, `resolvedTheme`, `effectiveMotion`, `createPreferenceScript(storageKey?, defaults?)`, and `preferenceScript`. The default key is `hyeonse-site-preferences`. `Preferences` has `theme`, `accent`, `density`, `corners`, and `motion`; defaults are `system`, `cobalt`, `comfortable`, `crisp`, `full`. Put the initial script in the document head before CSS paints. Valid saved choices take priority over site defaults. System reduced motion takes priority over the saved motion preference.

`./react` exports `PreferencesProvider`, `usePreferences`, `ThemeToggle`, and `PreferencesPanel`. The Provider accepts `storageKey?`, `eventName?` (default `hyeonse:preferences`), and `defaults?: Partial<Preferences>`; the hook gives `preferences`, `setPreference`, and `resetPreferences`. The controls accept `locale='ko'|'en'`. Match a custom script storage key and defaults with the Provider. Inspect the target framework's document-head and client-component integration before applying the example. Keep an app's existing preference persistence unless the requested integration calls for replacing it; otherwise plan its storage-key mapping before adding a Provider.

Base UI 1.9.0 leaves a WebKit VoiceOver focus-guard accessible-name issue unresolved ([upstream #5237](https://github.com/mui/base-ui/issues/5237)). Browser automation and DOM focus checks do not establish the actual VoiceOver reading experience; see `docs/code-freeze.md` inside the installed package for browser verification limits.
